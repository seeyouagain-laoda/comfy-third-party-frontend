# Comfy 第三方前端 · 保姆级使用教程

> **一句话**：一个跑在你自己电脑上的网页工作台，把「文生图、图生图、AI 视频、提示词优化、大模型对话」装进同一个界面。
> **纯本地**：后端只用 Python 标准库，前端是一个 HTML 文件，**不联网、不编译、不上传你的数据**。只有你主动填了「云端 API」时，那部分请求才会走外网。
> **这份是脱敏通用版**：所有密钥、局域网地址、个人专属内容都已移除；**模型文件名保留真实名称**（方便你照着下载）；**目录路径只隐去盘符与用户名**（用 `X:\...` 代替你的真实盘符，目录结构完全真实，可以照着建）。

## 1. 这是什么（能干什么 / 不能干什么）

### 1.1 能干什么

| 功能 | 干什么 | 需要什么 |
| --- | --- | --- |
| **文生图** | 打一段中文描述 → 出图 | ComfyUI + 显卡 + 底模 |
| **图生图 / 多图编辑** | 给图 + 说要求 → 改图（换衣服、改背景、扩图…） | 同上（编辑类底模） |
| **批量处理文件夹** | 选一个文件夹 → 里面所有图用同一句提示词逐个处理 | 同上 |
| **H3 视频** | 出 4~15 秒、**带音轨**的短视频；可用参考图锁角色 | 同上 + MiniMax-H3 系列模型 |
| **提示词优化** | 一句大白话 → 专业绘图 / 视频提示词 | 一个 OpenAI 兼容 API（本地或云端都行） |
| **大模型对话** | 聊天，可拖图片 / 文本附件，长对话自动压缩 | 本地模型 **或** 云端 API Key |

### 1.2 不能干什么（先说清楚，免得你期待落空）

- ❌ **不是「一键生成 5 分钟长片」的工具**。AI 视频模型单次只能出十几秒，长片必须「分镜 → 逐段生成 → 拼接」，第 12 章教你怎么做。
- ❌ **不训练模型**。LoRA 训练要用别家工具（如 kohya），本工具只负责「用」。
- ❌ **不会自动帮你下模型**。模型动辄几十 GB，得你自己下、自己放（第 7 章有目录表）。
- ❌ **不是云服务**。关掉电脑就没了；想让手机也能用，得自己配内网穿透（超出本文范围）。

### 1.3 界面长什么样

打开后是一个网页（默认 `http://127.0.0.1:8777`），用你**日常的 Chrome** 打开（书签、扩展、登录态都在，上手即用）。

## 2. 名词解释（小白必读）

看不懂就回来查，不用背。

| 名词 | 大白话解释 |
| --- | --- |
| **ComfyUI** | 一个开源的「AI 画图/画视频」引擎。它自己有一个网页界面（默认 `127.0.0.1:8188`），本工具是通过它的接口去驱动它 |
| **工作流（workflow）** | 一张「连线图」，描述 AI 出图的步骤顺序。本包 `workflows\` 里带了 2 个现成的 |
| **底模 / UNet / DiT** | 真正干活的「大脑」权重文件，通常几个 GB 到几十 GB |
| **LoRA** | 一个几十 MB 的「小补丁」，贴在底模上用来改变风格 / 学某个角色。可叠加 |
| **VAE** | 负责把 AI 的「抽象数字」翻译成肉眼能看的图片/视频，以及把视频翻译成声音 |
| **文本编码器（TE / CLIP）** | 负责把你的中文/英文提示词翻译成 AI 能懂的东西 |
| **GGUF / safetensors** | 两种模型文件格式。GGUF 常见于量化过的模型，safetensors 是通用安全格式 |
| **量化（Q4_K_M / int8 / fp8…）** | 把模型「压小」以省显存。Q4 比 int8 更小更省显存，但细节略差。数字越大越精细、越吃显存 |
| **显存（VRAM）** | 显卡自带的内存。**画图/画视频主要看显存，不是看内存**。8GB 能玩小模型，16GB 比较舒服，24GB+ 很爽 |
| **步数（steps）** | AI 打磨多少次。越多越细但越慢。加速模型（turbo）8 步就够，普通模型 20~30 步 |
| **CFG** | 「听提示词的强度」。Qwen-Image / Krea 这类新模型推荐 **1.0**（等于不额外加权） |
| **种子（seed）** | 随机数起点。**同一个种子 + 同一段提示词 = 同一张图**。`-1` 表示每次随机 |
| **denoise（重绘幅度）** | 图生图专用。`0.3` 轻微改，`0.75` 中等改，`1.0` 几乎重画 |
| **llama.cpp / llama-server** | 在本地跑大语言模型的引擎（对话用）。跑起来后会开一个 `127.0.0.1:8080` 的接口 |
| **Ollama** | 另一个本地大模型引擎，安装即用，更省心（但要用它自己的模型格式） |
| **OpenAI 兼容接口** | 一种行业通用的 API 格式。DeepSeek、GLM、Gemini 反代、本地 llama-server 都支持。填 `https://xxx/v1` + Key + 模型名就能用 |
| **T2VA / Ref2VA** | H3 视频的两种模式：**T2VA** = 只给文字（文生视频+音频）；**Ref2VA** = 给参考图 + 文字（参考图生视频+音频） |
| **首尾帧** | 你给它「第一帧长这样、最后一帧长那样」，它把中间补出来。做长视频衔接时非常有用 |
| **SAGE / VSA 加速** | 一种让视频生成更快、更省显存的加速开关。默认开启 |
| **<Picture N> / <Audio N> / <Video N>** | H3 提示词里指代「第 N 张参考图 / 第 N 个参考音频 / 第 N 段参考视频」的写法，**按你导入的顺序编号** |

## 4. 第一步：装 Python 与解压

### 4.1 装 Python

1. 打开 <https://www.python.org/downloads/windows/>，下载 **Python 3.11 或更高** 的 Windows installer (64-bit)。
2. 安装第一屏就**勾选 `Add python.exe to PATH`**（这一步忘了，后面启动脚本会找不到 Python）。
3. 一路「下一步」装完。
4. **验证**：按 `Win+R` → 输入 `cmd` → 回车 → 输入：

   ```bat
   python --version
   ```

   能看到 `Python 3.x.x` 就成功了。看不到就重装，注意勾选 PATH。

> **便携 Python 兜底**（公司电脑不让装软件、或系统 Python 装不干净时最有用）。
> 启动脚本按下面的顺序找 Python，**找到就用，找不到才往下走**：
>
> | 顺序 | 找哪里 | 怎么弄 |
> | --- | --- | --- |
> | 1 | 本包 `python\pythonw.exe` 或 `python\python.exe` | 把便携版 Python 整个解压到本包 `python\` 子目录 |
> | 2 | 本包 `venv\Scripts\pythonw.exe` 或 `venv\Scripts\python.exe` | 在本包目录里执行 `python -m venv venv`（实测可用） |
> | 3 | 系统 PATH 里的 `pythonw.exe` / `python.exe` | 装 Python 时勾上 "Add python.exe to PATH" |
>
> **实测**：只要第 1 或第 2 条存在，**哪怕系统里完全没装 Python，双击 bat 也能正常跑起来**
> （本包后端只用 Python 标准库，不需要装任何第三方包）。
> 想确认最后用了哪个 Python？看 `logs\launcher.log` 里的 `后端进程 pid=... (路径)`。

### 4.2 解压本包

1. 把 `Comfy第三方前端.zip` 解压到任意目录。
   **本包自己放在中文目录下没问题**（实测过：`D:\_zt\Comfy第三方前端\` 能正常启动），所以不用为了它专门改目录名。
   但**两个地方建议用纯英文、不含空格的路径**：① **ComfyUI 的安装目录**；② **模型文件所在目录**。
   这两个是第三方工具链（PyTorch / ComfyUI / 各种自定义节点）在啃的路径，中文和空格是它们的经典踩坑点，别给自己找麻烦。
2. 解压后目录里应该至少有：

   ```
   comfy_studio.py  comfy_studio.html  comfy_studio_launch.py
   comfy_control.py  comfy_engine.py    comfy_studio_config.json
   启动Comfy第三方前端.bat  requirements.txt  workflows\  README.md  docs\保姆级教程.md（就是本文）
   预览.png（界面实拍图，给你对样子用的）
   ```

### 4.3 先跑一下（可选，但推荐）

双击 `启动Comfy第三方前端.bat`，看浏览器能不能打开页面。左上角显示 **Comfy 第三方前端** 就成功了 —— 这时候你还没配任何模型，但页面、提示词优化、对话已经能用。

> **想做个桌面快捷方式？** 右键 `启动Comfy第三方前端.bat` → 「显示更多选项」→「发送到」→「桌面快捷方式」，然后右键快捷方式改图标即可。

## 5. 第二步：装绘图引擎 ComfyUI

ComfyUI 是真正出图的引擎，本工具只是它的「遥控器」。**两种装法任选其一**。

### 5.1 方式一：ComfyUI-Desktop（图形安装器，推荐小白）

1. 打开 <https://www.comfy.org/download>，下载 **ComfyUI-Desktop** 的 Windows 安装包，双击安装。
2. 打开 ComfyUI-Desktop，它自带 Python 环境，点界面里的 **Install** 装好 PyTorch（CUDA 版，几个 GB，耐心等）。
3. 启动后点 **Open in Browser**，确认地址是 `http://127.0.0.1:8188`。
4. **记下它的安装目录**（后面填配置要用）。典型结构：

   ```
   X:\Comfy-Desktop\ComfyUI\ComfyUI\
   ├── main.py                  ← 启动入口
   ├── .venv\Scripts\python.exe ← 它的 Python
   ├── models\                  ← 模型都放这里
   └── output\                  ← 出图存这里
   ```

> 优点：不用敲命令、自动配好 PyTorch/CUDA。
> 缺点：自定义节点和它内部环境绑定，进阶玩家受限。

### 5.2 方式二：官方 git 版（可控，适合进阶）

```bat
:: 1) 先装 Git（若没有）：https://git-scm.com/download/win ，一路默认
:: 2) 克隆 + 建虚拟环境
git clone https://github.com/comfyanonymous/ComfyUI.git X:\ComfyUI
cd X:\ComfyUI
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
:: 3) 启动（默认监听 8188）
python main.py --listen 127.0.0.1 --port 8188
```

启动后浏览器开 `http://127.0.0.1:8188`，能看到节点画布即成功。

### 5.3 装 comfy-cli（两种装法都要）

comfy-cli 负责把本包自带的 `.json` 工作流转成 ComfyUI 能接受的 API 格式。

```bat
pip install comfy-cli
```

> ⚠️ **必须装在「跑后端的那个 Python」里** —— 就是 `启动Comfy第三方前端.bat` 实际用的那个 Python：
>
> | 你机器上是哪种情况 | 正确命令 |
> | --- | --- |
> | 包内有 `python\`（便携版） | `python\python.exe -m pip install comfy-cli` |
> | 包内有 `venv\` | `venv\Scripts\python.exe -m pip install comfy-cli` |
> | 都没有，用系统 Python | 直接 `pip install comfy-cli` |
>
> **装到 ComfyUI 自己的 venv 里是没用的。** 后端跑在自己的 Python 里，压根不看 ComfyUI 那个 venv。
> （这一点极易搞错，实测过：把 comfy-cli 装进 ComfyUI 的 venv，页面「依赖自检」照样报缺失。）
>
> **不知道该用哪个 Python？** 先双击一次 bat 启动，然后打开 `logs\launcher.log`，
> 找 `后端进程 pid=... (C:\...\python.exe)` 那一行 —— 括号里的路径就是答案，
> 用它去 `-m pip install comfy-cli`。
>
> 没装的话：页面「设置 → 依赖自检」会报它缺失，文生图 / 图生图会失败；但页面、对话、提示词优化照样能用。

### 5.4 让 ComfyUI 支持 H3 视频（要生成视频才需要）

H3 视频走的是 ComfyUI 的**原生 MiniMax-H3 节点**，所以：

1. **ComfyUI 版本要够新**（能加载到 `MiniMaxH3ImageToVideo` / `MiniMaxH3ReferenceToVideo` / `MiniMaxH3SigmaShift` 这几个节点）。
   验证方法：启动 ComfyUI → 在画布上双击搜索 `MiniMaxH3`，能搜到就 OK。
2. **不需要**额外装 VideoHelperSuite。
   本工具会优先用 ComfyUI 自带的 `CreateVideo + SaveVideo` 节点（零额外依赖）；只有在老版本 ComfyUI 上没有这两个节点时，才回退到 VHS 插件。
3. 把 H3 的 4 类模型文件放好（第 7 章有目录表）。

> 升级 ComfyUI：Desktop 版在它的界面里点更新；git 版在 ComfyUI 目录里 `git pull` 然后重装依赖。

## 6. 第三步：装本地对话引擎（llama.cpp / Ollama）

**只有想「本地大模型聊天」才需要**（也就是模式 C）。二选一。

### 6.1 方式一：llama.cpp（推荐，直接吃 GGUF 文件）

1. 打开 <https://github.com/ggml-org/llama.cpp/releases>，下载 Windows 的 CUDA 版（形如 `llama-server-cuda-cu12.x-win.zip`），解压到任意目录（例如 `X:\llama`）。
2. 准备一个 GGUF 对话模型（例如 Qwen3 系列的 IQ3_XXS 量化版）。
3. 启动本地服务：

```bat
cd /d X:\llama
llama-server.exe ^
  --model "X:\你的模型目录\你的模型.gguf" ^
  --ctx-size 65536 ^
  --n-gpu-layers 99 ^
  --host 0.0.0.0 --port 8080
```

| 参数 | 什么意思 | 怎么调 |
| --- | --- | --- |
| `--ctx-size` | 上下文长度（能记住多少字） | 越大越吃显存。64K 是常见值，不够显存就降到 32K |
| `--n-gpu-layers` | 多少层放显卡上跑 | `99` = 尽量全放显卡。显存不够会启动失败 → 调小（如 40） |
| `--port` | 服务端口 | 默认 8080，被占用就换 |

4. 起好后访问 `http://127.0.0.1:8080`，能看到状态页即成功。
5. 配置里 `chat_targets.local.api_url` 填 `http://127.0.0.1:8080/v1`，`model` 填你的模型名。

> **想开 Qwen3 的「思考模式」？** 需要两件事同时满足：
> ① llama-server 启动时带上思考开关；② 请求里透传 `enable_thinking`。
> 本工具的启动器配置 `engines_launch.llm.thinking` 默认就是 `on`，配合页面使用即可。

### 6.2 方式二：Ollama（最省心）

1. 打开 <https://ollama.com/download/windows> 下载安装，装完自动起服务（端口 11434）。
2. 拉一个模型：`ollama pull qwen2.5:14b`（换成你想要的）。
3. 配置里 `chat_targets.ollama.api_url` 默认 `http://127.0.0.1:11434/v1`，`model` 填 `qwen2.5:14b`。

> 已有 GGUF 想用 Ollama 跑？写个 Modelfile（内容一行 `FROM 你的.gguf`），然后 `ollama create 我的模型 -f Modelfile`。

## 7. 第四步：模型放哪

### 7.1 通用规则

ComfyUI 只会去**它自己目录下的 `models\` 子目录**里找模型。所以：

```
X:\你的ComfyUI\
└── models\
    ├── diffusion_models\    ← 底模（画图 / 画视频的「大脑」）
    ├── vae\                 ← VAE
    ├── text_encoders\       ← 文本编码器
    ├── loras\               ← LoRA
    ├── audio_encoders\      ← 音频相关（部分工作流用）
    └── clip_vision\         ← 视觉编码器（部分工作流用）
```

> **目录名对不上？** 不同 ComfyUI 版本略有差异：`diffusion_models` 旧版叫 `unet`，`text_encoders` 旧版叫 `clip`。以你本机实际为准。
> **不确定放哪？** 先在页面点一次「生成」，报错时 ComfyUI 会在节点上红框提示它期望的路径，按提示挪即可。

### 7.2 画图需要的文件（以 Qwen-Image 2.1 为例）

| 放在哪 | 文件名（示例，作者用的这套） | 大约多大 | 作用 |
| --- | --- | --- | --- |
| `models\diffusion_models\` | `qwen-image-2.1-Q4_K_M.gguf` | ~4.6 GB | 文生图底模 |
| `models\diffusion_models\` | Qwen-Image-Edit 系列的编辑底模 | 几 GB | 图生图 / 多图编辑 |
| `models\vae\` | `qwen_image_vae.safetensors` | 几百 MB | 图像 VAE |
| `models\text_encoders\` | `qwen3vl_4b_fp8_scaled.safetensors` | 几 GB | 文本编码器 |
| `models\loras\` | 你的 LoRA | 几十 MB ~ 几 GB | 可选，风格 / 角色 |

**去哪下**：打开 <https://huggingface.co> ，在搜索框里直接搜**文件名**或**模型名**（如 `Qwen-Image-2.1`、`qwen_image_vae.safetensors`）。
很多模型有官方出的「ComfyUI 预转换版」（直接就是 GGUF / safetensors），搜到后下载 → 按上表放好即可。

> **国内下载慢？** HuggingFace 有镜像站；或先用浏览器 / 迅雷下到本地再挪进去。文件很大，别用浏览器下到一半就关。

### 7.3 H3 视频需要的文件（4 类，缺一不可）

| 放在哪 | 文件名（示例） | 大约多大 | 作用 |
| --- | --- | --- | --- |
| `models\diffusion_models\` | `Minimax-h3_Singularity_ref2va_v1.3_int8.safetensors` | ~34 GB | H3 底模（视频+音频） |
| `models\text_encoders\` | `qwen3vl_32b_minimax_h3_int8_convrot.safetensors` | ~27 GB | H3 专用文本编码器（也有更小的 15.7GB 量化版） |
| `models\vae\` | `minimax_h3_video_vae_int8_convrot.safetensors` | ~2.8 GB | 视频 VAE（把潜变量解码成画面） |
| `models\vae\` | `minimax_h3_audio_vae_fp32.safetensors` | ~0.6 GB | 音频 VAE（解码出音轨） |
| `models\loras\`（可选） | `h3-realism-people-t2v-i2v-r2v.safetensors` 等 | 100~200 MB | 让画面更写实 / 特定风格 |

> **重要**：文件总量加起来 ~64 GB，**但不需要一次性全部塞进显存**。引擎会按需加载/卸载，16GB 显存实测能跑（见第 12.2 章）。

## 8. 第五步：启动与关闭

### 8.1 启动

**双击 `启动Comfy第三方前端.bat`**。它会：

1. 静默启动本地后端（端口 8777，**不弹黑框**）；
2. 等后端就绪；
3. 用你**日常的 Chrome** 打开 `http://127.0.0.1:8777`。

看到网页打开、左上角显示 **Comfy 第三方前端** 就成功了。

其它启动参数（命令行用法）：

```bat
启动Comfy第三方前端.bat --tab          :: 用系统默认浏览器开标签页
启动Comfy第三方前端.bat --no-browser   :: 只起后端，不弹浏览器（调试用）
启动Comfy第三方前端.bat --stop         :: 停掉正在跑的后端
```

### 8.2 关闭

- **直接关掉浏览器窗口（或那个标签页）** 即可。后端发现「一个页面都不剩」并**持续 15 秒**后，会自动**停掉引擎、退出进程**。
- ⚠️ **它会连正在跑的引擎一起停掉** —— 所以**做长视频 / 大批量出图时，千万别关标签页**，否则任务被中断、前面白跑。
  想让它「没页面时也别退」，把配置里 `app.auto_exit_no_heartbeat` 改成 `false`（第 9.6 章）。
- 想立刻全关：双击 `启动Comfy第三方前端.bat --stop`（等价于页面右上角「全部停止并退出」）。
- **多个标签页是安全的**：关掉其中一个只注销它自己，不会把整个后端关掉（要等到一个都不剩才收尾）。
- **刷新页面不会误杀**：注销 → 重新登记之间有几秒空档，那个 15 秒宽限期就是为它留的。
- 后端**没在跑**的时候执行 `--stop` 也不会报错，它会打印「后端未在运行或请求失败」然后正常退出。

### 8.3 启动绘图 / 视频引擎

页面顶栏有引擎按钮（**ComfyUI 绘图** / **H3 视频** / **本地大模型**）：

- 点一下 → 启动（首次启动 ComfyUI 要 30~90 秒，别急）；
- 再点一下 → 停止；
- **同一时刻只能开一个**（16GB 显存带不动两个）。

> 想「一次点开就连 ComfyUI 一起拉起来」？把配置里 `engines_launch.comfy.enabled` 改成 `true`，并填好 `exe` / `cwd`（第 9 章）。

## 9. 第六步：改配置（核心）

配置文件是 **`comfy_studio_config.json`**（和脚本同目录）。**改完保存 → 重启 `启动Comfy第三方前端.bat` 生效。**

### 9.1 关于「占位符」——先看这一条

配置里所有 `X:\...` 开头的路径都是**占位符**，意思是「换成你自己机器上的真实目录」：

| 配置里的占位符 | 你应该换成 |
| --- | --- |
| `X:\你的ComfyUI` | 你的 ComfyUI 根目录，例如 `D:\ComfyUI` |
| `X:\你的ComfyUI\venv\Scripts\python.exe` | 你的 ComfyUI 的 Python，例如 `D:\ComfyUI\venv\Scripts\python.exe` |
| `X:\你的ComfyUI\models\diffusion_models` | 你的底模目录 |
| `X:\你的模型目录` | 你放模型的地方 |
| `X:\你的llama.cpp` | 你解压 llama.cpp 的目录 |

**相对路径不用改**（如 `output`、`archive`、`workflows/txt2img.json`），它们相对本包目录。

> **⚠️ 代码文件（`.py`）里也有同样的占位符，但你不用管它们。** 那些只是「兜底默认值」，真正生效的是本配置文件。改配置就够了。

### 9.2 最省事的路子：先跑起来，再用界面填

**轻量档（只用提示词优化 / 云端对话）几乎不用改配置**：

1. 启动 → 打开页面；
2. 顶栏「优化器」旁边点 **`＋ 添加模型`**；
3. 填：名称 / 接口地址（`https://xxx/v1`）/ API Key / 模型名；
4. 点「测试连接」（会真发一条最小请求验证），通过后保存。

搞定。提示词优化立即可用。

### 9.3 绘图档必改字段

| 字段路径 | 改成什么 | 说明 |
| --- | --- | --- |
| `comfy_url` | `http://127.0.0.1:8188` | ComfyUI 默认地址，一般不用改 |
| `engines.image` | 同上 | 保持一致即可 |
| `engines_launch.comfy.enabled` | `true` | 允许启动器自动拉起 ComfyUI |
| `engines_launch.comfy.exe` | 你的 ComfyUI 的 python.exe | 例：`D:\ComfyUI\venv\Scripts\python.exe` |
| `engines_launch.comfy.cwd` | 你的 ComfyUI 根目录 | 例：`D:\ComfyUI` |
| `engines_launch.comfy.port` | `8188` | 与 ComfyUI 监听端口一致 |
| `model_dirs.unets` | 你的底模目录 | 例：`D:\ComfyUI\models\diffusion_models` |
| `model_dirs.loras` | 你的 LoRA 目录 | 例：`D:\ComfyUI\models\loras` |
| `workflows.txt2img` / `img2img` | 保持 `workflows/txt2img.json` 等 | 也可换成你自己的 ComfyUI 工作流 |

填好 `model_dirs` 后，去页面「设置 → 模型库」点 **导入底模**，它会扫目录把模型列进下拉框，不用手填路径。

### 9.4 H3 视频必改字段

| 字段路径 | 改成什么 | 说明 |
| --- | --- | --- |
| `h3.mode` | `comfy` | 保持默认。`comfy` = 用本机 ComfyUI 跑（16GB 可跑） |
| `h3.comfy_url` | `http://127.0.0.1:8188` | 与 ComfyUI 一致 |
| `h3.engine_exe` | 你的 ComfyUI python.exe | 同 9.3 |
| `h3.engine_workdir` | 你的 ComfyUI 根目录 | 同 9.3 |
| `h3.model_path` | H3 底模文件名 | 如 `Minimax-h3_Singularity_ref2va_v1.3_int8.safetensors` |
| `h3.te_path` | H3 文本编码器文件名 | 如 `qwen3vl_32b_minimax_h3_int8_convrot.safetensors` |
| `h3.vae_video_path` | 视频 VAE 文件名 | 如 `minimax_h3_video_vae_int8_convrot.safetensors` |
| `h3.vae_audio_path` | 音频 VAE 文件名 | 如 `minimax_h3_audio_vae_fp32.safetensors` |

> **模型名填文件名还是全路径？** 两种都行。填文件名时 ComfyUI 会去自己的 `models\` 里找；找不到就填全路径。

### 9.5 本地对话（模式 C）必改字段

| 字段路径 | 改成什么 |
| --- | --- |
| `chat_targets.local.api_url` | `http://127.0.0.1:8080/v1`（llama.cpp） |

| `chat_targets.ollama.model` | 你的 Ollama 模型名 |

### 9.6 其它常用字段

| 字段 | 作用 | 默认 |
| --- | --- | --- |
| `listen_port` | 本工具后端端口，冲突时改 | `8777` |
| `output_dir` / `out_dir` | 出图保存目录 | 本包内 `output\` |
| `output_dirs` | 额外扫描的目录（ComfyUI 自己的 output 也在里面时，画廊才能显示） | 本包内 `output\` |
| `archive_root` | 按「模块 / 模型 / 日期」归档的根目录 | 本包内 `archive\` |

### 9.7 关于「模型组」

`groups` 是「一键配方」：把 **底模 + 适用页面 + 默认参数** 打包，页面上选一下就能整体切换。默认是空数组 `[]`。想用就照这个格式加：

```json
"groups": [
  {
    "id": "g-qwen21",
    "name": "千问 2.1 组",
    "arch": "Qwen-Image-2.1",
    "unet": "qwen-image-2.1-Q4_K_M.gguf",
    "pages": ["txt2img", "img2img"],
    "defaults": { "steps": 8, "cfg": 1.0, "width": 1024, "height": 1024 },
    "note": "文生图/图生图同源"
  }
]
```

> ⚠️ `groups` **必须是数组**（方括号），不能是对象（花括号）。

## 10. 各功能怎么用（逐页讲解）

### 10.1 文生图

1. 先在「设置 → 模型库」导入底模（或在页面下方「模型组」选一个现成配方）。
2. 在「正向描述」框写中文（工作流走 Qwen 文本编码器，**中文即可**）。
   例：`一位身着异域服饰的女子在沙漠中弹奏乐器，音符化为环绕飞舞的发光丝绸`。
3. 「优化器」选一个引擎，可点 **结构化描述（AI）** 让 AI 把口语扩写成专业提示词；
   也可以点 **📷 反推描述**，上传一张图让 AI 描述它。
4. 调参数：步数 / CFG / 尺寸 / 张数（默认已给一组好用的：8 步、CFG 1.0、1024×1024）。
5. 点 **生成**（按钮在页面右上角）。进度和日志在页面底部。

**批量描述**：把「描述模式」切到 **批量描述**，在文本框里**每行写一条提示词**，点生成 → 它会一条条跑完。中途可点「暂停生成」中断剩余。

### 10.2 图生图 / 多图编辑

1. 在「参考图」区点 **添加图片** 上传 1~2 张图（多图编辑请先切到「多参考图」）。
2. 写正向描述，说明你想改什么。例：`图中的女孩的衣服换成汉服，人物保持一致`。
3. 调 **重绘幅度 denoise**：`0.3` 轻微改 / `0.75` 中等 / `1.0` 几乎重画。
4. 点右上角 **▶ 生成**。

> **提示**：图片会按最长边等比缩放，防止超显存。

### 10.3 批量处理文件夹（图生图页的特色功能）

适合「我有 100 张产品图，全都要换成同一个背景」这种活。

1. 先把**提示词写好**（比如 `把背景换成纯白摄影棚`）。
2. 点 **📁 批量处理文件夹** → 选一个文件夹。
3. 它会：把文件夹里每张图上传 → 用**同一句提示词**逐个生成 → 进度条 + 日志实时显示 → 结束后报「成功 X / 共 Y 张」。
4. 中途可以点「暂停生成」停下来。

**规则**：
- 支持的图片格式：`png` / `jpg` / `jpeg` / `webp` / `bmp` / `gif` / `avif`；
- 文件夹里的图当 **image_1**（被处理的对象）；
- 如果你在上方「图槽」里放了一张图，那张会当 **image_2**（风格参考）；图槽为空则用原图自身做自编辑；
- 提示词必须**先写好**，否则会提示「请先在上方写好提示词，再批量处理」。

### 10.4 模型库 / 模型组

- **模型库**：在「设置」页，点「导入底模 / 导入 LoRA」会去扫 `model_dirs` 里配置的目录，把模型列出来。不用手填路径。
- **模型组**：把一套配方（底模 + 页面 + 参数）存下来，页面上点一下就整体切换。
- **LoRA 叠加**：勾选即叠加，与底模互不影响。如果工作流里没有 LoRA 加载节点，后端会在日志里**明确提示**（不会静默忽略）。

### 10.5 设置 → 依赖自检（日志与诊断）

这一块**只做一件事**：检查 `comfy-cli` 有没有装在「跑后端的那个 Python」里。

- ✅ 绿字 = 装了，文生图 / 图生图可用；
- ❌ 红字 = 没装（或装错了 Python），修法见第 5.3 章。

**它不检查** ComfyUI 连通性、模型目录、显存 —— 那些看别处：

| 想确认什么 | 去哪看 |
| --- | --- |
| ComfyUI 通不通 | 顶栏的状态点（「ComfyUI 未运行」/「已连接」）+「检测运行状态」按钮 |

## 12. 【重点】H3 视频完全指南

这一章是本文最有价值的部分，**建议从头读完**。

### 12.1 H3 是什么 / 能出多长

- H3 = MiniMax 系列的视频生成模型（作者用的是社区量化版，带**音轨**）。
- 两种模式：
  - **T2VA**（`image` 模式）：只给文字 → 文生视频 + 音频；
  - **Ref2VA**（`reference` 模式）：给参考图 + 文字 → 参考图生视频 + 音频。
- **单次生成时长有限**：实践区间大约 **4~15 秒/条**（帧数是按 `17k+5` 的网格向上取整的，1 秒 ≈ 24 帧）。
  想要更长 → 必须**分批生成再拼接**（第 12.5 章手把手教）。

> ⚠️ 「生成模式」这个下拉在 `comfy` 模式下其实**不影响流程**——本工具会自己判断：**参考图槽里有图就走 Ref2VA，没图就走 T2VA**。所以别纠结这个下拉，看参考图槽就行。

### 12.2 显存真相：16GB 到底能不能跑？（能！）

**结论：能跑。** 实测数据：

| 项目 | 数值 |
| --- | --- |
| 测试显卡 | RTX 5060 Ti **16GB** |
| 峰值显存占用 | **约 14283 MiB（≈14 GB）** |
| 单条生成耗时 | 约 64~111 秒（20 步 + 4 步 LoRA + SAGE 加速） |
| 输出规格 | 768×576 / 24fps / 带 AAC 音轨 |

**为什么模型文件有 64GB 却只要 14GB 显存？**
因为引擎是**按需加载 / 用完卸载**的，不是把整个模型一次性搬进显存。你看到的「需要 48GB 显存」的说法，只适用于**另一种模式**（把任务甩给远程 llama-server 端点），不是本机 ComfyUI 模式。

**如果你显存更小（8~12GB）怎么办？**
- 调小 `stage1_w` / `stage1_h`（一阶段分辨率），例如 `640×480`；
- 时长先设 4~5 秒试水；
- 步数降到 8；
- 关掉 LoRA；
- 关掉 SAGE/VSA 加速（加速有时会额外吃一点显存）。

**如果你是 24GB+**：可以把 `stage2_w` / `stage2_h` 拉高（两阶段潜空间放大），画质更好。

### 12.3 六段式提示词：逐段讲解

H3 的提示词不是「一句话」，而是**结构化的六段**。界面里已经有对应的分栏输入框，填好点「组装到上方」即可拼成完整提示词。

| 段名 | 中文意思 | 写什么 | 示例 |
| --- | --- | --- | --- |
| `subject_definitions` | **主体定义** | 把画面里会出现的东西**编号定义**清楚 | `Picture 1：一位 25 岁东亚女性，黑长发，米色风衣。Picture 2：雨夜霓虹街道` |
| `summary` | **一句话概括** | 整段视频发生了什么（一句） | `女子在雨夜霓虹街头缓慢转身看向镜头` |
| `retention_analysis` | **保留分析** | 说明参考图里哪些特征**必须保持不变** | `保持面部特征、发型、风衣颜色与材质完全一致` |
| `detailed_description` | **详细描述** | 按时间顺序写镜头：景别、动作、运镜、光线、环境 | `0-3s 中景，女子侧身站立，雨滴落下；3-6s 镜头缓慢推近…` |
| `overall_soundscape` | **环境音** | 场景里的**现场声音** | `雨声、远处车流声、脚步声` |
| `non_diegetic_music` | **配乐** | 画面外的背景音乐 | `低沉的合成器氛围乐，缓慢节奏` |

**写法要点：**
1. **主体定义要编号**，后面所有段落都用 `Picture 1` / `Picture 2` 指代，不要写「那个女孩」。
2. **详细描述按时间轴写**（`0-3s…3-6s…`），模型对时间轴敏感。
3. **声音一定要写**。很多人只写画面，结果出来的视频是哑的——不是模型不行，是你没告诉它要什么声音。
4. 想要**纯环境音不要配乐**？把 `non_diegetic_music` 写成 `无背景音乐`。

**一个可以直接抄的模板：**

```
subject_definitions:
Picture 1: a 25-year-old East Asian woman, long black hair, beige trench coat, holding a black umbrella.
Picture 2: a rainy neon-lit street at night, wet asphalt with reflections.

summary:
The woman slowly turns her head to look at the camera on a rainy neon street.

retention_analysis:
Keep the facial features, hairstyle, and the color and material of the trench coat exactly consistent with Picture 1. Keep the neon color palette and wet reflections from Picture 2.

detailed_description:
0-3s: medium shot, the woman stands in profile under the umbrella, rain falls in front of the neon signs.
3-6s: the camera slowly pushes in; she turns her head toward the lens, water droplets on her face.
6-8s: close-up, she looks directly at the camera, a faint breath visible in the cold air.

overall_soundscape:
Steady rain, distant traffic, faint footsteps on wet asphalt.

non_diegetic_music:
Low ambient synth pad, slow tempo, melancholic.
```

> **中文也行**。工作流走的是 Qwen3-VL 文本编码器，中文理解没问题。但**主体定义的编号写法要保持一致**。

### 12.4 参考图九宫格分镜法（角色一致性的关键）

**问题**：同一个角色，生成第 1 镜和第 5 镜，脸不一样 —— 这是所有 AI 视频的通病。

**解法：九宫格 + 角色圣经。**

#### 九宫格是什么

把**同一个角色**做成一张 3×3 的「九宫格图」（每格一个不同角度/姿势/表情）：

```
┌────────┬────────┬────────┐
│ 正面   │ 3/4 侧 │ 侧面   │
├────────┼────────┼────────┤
│ 背面   │ 仰视   │ 俯视   │
├────────┼────────┼────────┤
│ 微笑   │ 严肃   │ 惊讶   │
└────────┴────────┴────────┘
```

**为什么正好用九宫格**：H3 的参考图上限是 **9 张**（`<Picture 1>` ~ `<Picture 9>`），九宫格切开来正好 9 张，一张不多一张不少。

#### 怎么做（三种办法）

| 办法 | 怎么做 | 适合 |
| --- | --- | --- |
| **A. AI 生成九宫格** | 用文生图，提示词写「character sheet, 3x3 grid, nine views of the same character: front, 3/4, side, back, low angle, high angle, smiling, serious, surprised」→ 出图 → 自己裁成 9 张 | 没有现成素材 |
| **B. 用现成多角度图** | 手头已有角色的多角度图（三视图、设定集）→ 直接裁 | 有素材 |
| **C. 用视频截帧** | 用一段这个角色的视频，隔几帧截一张，凑 9 张 | 想要动态神态 |

裁好后，把 9 张图**按固定顺序**导入 H3 页的「参考图片」槽（顺序很重要！），然后点 **「引用」** 按钮把 `<Picture N>` 标签写进提示词。

#### 角色圣经（Character Bible）

准备一段**固定不变的身份描述句**，**每一条**镜头的提示词都原样带上：

```
subject_definitions:
Picture 1-9: the same young woman, East Asian, 25 years old, long straight black hair with a center part,
dark brown eyes, a small mole under her left eye, slim build, wearing a beige trench coat over a white shirt.
Picture 1 is her front view, Picture 2 is her 3/4 view, Picture 3 is her side view...
```

**要点：**
- 特征要写**具体且唯一**（痣、发型分缝、瞳色），不要写「漂亮」「年轻」这种模糊词；
- 这段文字**逐字不变**地复制到每条提示词里 —— 这就是「锁定」的原理；
- 9 张图**每次都要一起带**（或者至少带同一套里最关键的 3~4 张），不要这镜带 3 张、下一镜换 2 张。

#### 素材组：省得每次重新导入

H3 页有 **「已保存的素材组」**：

- 点 **「保存当前素材 + 描述为一组」** → 把当前的参考图 + 提示词整体存下来（存在浏览器本地）；
- 下次点一下那个组名 → **一键回落**（素材和提示词全部还原）。

> 做长视频时这个功能非常关键：**先建好「角色素材组」，每条镜头都从它回落，改的只是详细描述那一段**。

### 12.5 分批生成长视频（手把手）

**核心思想**：AI 单次只能出十几秒，所以长视频 = **分镜表 + 逐镜生成 + 拼接**。

#### 步骤 1：写分镜表

先别急着点生成，用纸或 Excel 写清楚每一镜：

| 镜号 | 时长 | 画面（详细描述） | 声音 | 参考图 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 01 | 6s | 中景，女子撑伞站在雨夜街头，侧身 | 雨声、车流 | 九宫格全套 | 开场 |
| 02 | 5s | 推近，她转头看向镜头 | 雨声 + 呼吸 | 九宫格全套 | 承接 01 尾帧 |
| 03 | 8s | 特写，她开口说话 | 台词 + 雨声 | 九宫格全套 | |
| 04 | 6s | 拉远，她转身走入霓虹深处 | 雨声渐弱 + 配乐起 | 九宫格全套 | 收尾 |

#### 步骤 2：逐镜生成

**方式 A：用「批量描述」模式（适合镜头间没关联的）**

1. H3 页把「描述模式」切到 **批量描述**；
2. 文本框里**每行写一条完整提示词**（每条都带角色圣经那段）；
3. 点提交 → 它会一条条跑完。

**方式 B：用「素材组」逐镜生成（推荐，适合有角色一致性的）**

1. 先建好角色素材组（第 12.4 章）；
2. 每一镜：点素材组 → 回落 → 只改 `detailed_description` 那一段 → 点提交；
3. 生成完这一镜，再点素材组回落 → 改下一镜的描述 → 提交。

> **为什么推荐 B**：因为长视频里「角色一致性」比什么都重要，而素材组能保证每一镜的参考图完全一致。

**命名规范（很重要）**：生成出来的文件会叫 `ComfyStudio_H3_00001_.mp4` 这种。**每生成完一镜，立刻把它重命名**成：

```
01_开场_雨夜撑伞.mp4
02_转头看镜头.mp4
03_特写说话.mp4
04_走入霓虹.mp4
```

按 `01_` `02_` 排序，后面拼接时不会乱。

#### 步骤 3：拼接成一条长片

用 **ffmpeg**（免费，<https://ffmpeg.org/download.html>，下载后把 `bin` 目录加进 PATH，或直接用全路径）。

**做法 A：文件列表拼接（推荐，快）**

1. 把要拼的 mp4 放进同一个文件夹，例如 `D:\h3\shots\`；
2. 在该文件夹里新建 `list.txt`，内容（**注意用正斜杠或双反斜杠**）：

   ```
   file '01_开场_雨夜撑伞.mp4'
   file '02_转头看镜头.mp4'
   file '03_特写说话.mp4'
   file '04_走入霓虹.mp4'
   ```

3. 在该文件夹打开 cmd，执行：

   ```bat
   ffmpeg -f concat -safe 0 -i list.txt -c copy 成品.mp4
   ```

   `-c copy` 表示**不重新编码**，秒完成、无损。前提是各段的分辨率 / 帧率 / 编码一致（H3 出来的都一样，所以没问题）。

**做法 B：直接命令行拼（段数少时）**

```bat
ffmpeg -i 01.mp4 -i 02.mp4 -i 03.mp4 -filter_complex "[0:v][0:a][1:v][1:a][2:v][2:a]concat=n=3:v=1:a=1[v][a]" -map "[v]" -map "[a]" -c:v libx264 -crf 18 成品.mp4
```

（这条会重新编码，慢一些，但能处理参数不一致的情况。）

**做法 C：加淡入淡出转场**

```bat
ffmpeg -i 01.mp4 -i 02.mp4 -filter_complex "[0:v][1:v]xfade=transition=fade:duration=0.5:offset=5.5[v];[0:a][1:a]acrossfade=d=0.5[a]" -map "[v]" -map "[a]" 成品.mp4
```

#### 步骤 4：接缝不自然怎么办？

这是长视频最大的痛点。三个实用技巧：

| 技巧 | 怎么做 |
| --- | --- |
| **首尾帧衔接** | 把上一镜的**最后一帧**截出来，作为下一镜的参考图（放进参考图槽，提示词里写明「以 `<Picture 1>` 为起始帧」）。这样两镜的画面能连上 |
| **统一全局风格句** | 每一镜的 `subject_definitions` 里都加上同一句环境描述（光线、色调、天气），风格就不会跳 |
| **转场遮瑕** | 两镜之间加 0.3~0.5 秒的淡入淡出（见做法 C），用转场掩盖不一致 |

### 12.6 首尾帧衔接（做「动作连续」的镜头）

想让「转身」这个动作分两镜拍（第一镜转到一半，第二镜接着转完）：

1. 生成第 1 镜；
2. 从第 1 镜的**尾帧**截图 → 存成 `tail_01.png`；
3. 第 2 镜：把 `tail_01.png` 放进参考图槽；
4. 提示词里写：`以 <Picture 1> 作为起始帧，继续完成转身动作，最后面向镜头`；
5. 生成 → 两镜接起来动作是连贯的。

> **老实说**：comfy 模式下 H3 走的是 Ref2VA（参考图生视频），它**不是专门的「首尾帧插帧」模型**。上面这套是**实践中的有效做法**（因为参考图会强约束首帧画面），但不保证 100% 精确。想要更严格的连续性，就多用第 4 步的技巧 + 转场遮瑕。

### 12.7 参数怎么调

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| 采样步数 | **8~10** | 配 8 步加速 LoRA 时用 8；不用 LoRA 可以 10~20 |
| 种子 | `-1`（随机） | 想复现某条 → 记下它的种子，填回去 |
| 时长（秒） | **4~8 起步** | 先短后长。跑通了再往上加 |
| 帧率 FPS | **24** | H3 原生 24fps，一般不用改 |
| SAGE / VSA 加速 | **开启** | 更快更省显存 |
| 1 阶段宽/高 | `768×576` | 主分辨率。显存不够就降到 `640×480` |
| 2 阶段宽/高 | `1024×780` | 潜空间放大后的分辨率。显存不够就和 1 阶段持平 |
| LoRA 强度 | `1.0` | 低于 1 容易糊 |

### 12.8 实战时间与显存参考

| 场景 | 显存峰值 | 单条耗时 | 备注 |
| --- | --- | --- | --- |
| 768×576 / 5s / 20 步 + LoRA + SAGE | ≈14 GB | 64~111 秒 | RTX 5060 Ti 16GB 实测 |
| 768×576 / 2s / 10 步（最小验证） | ≈14 GB | 约 40~60 秒 | 用来验证「环境是否配好」 |

> **第一条视频建议这样试**：时长 2 秒、步数 10、不带 LoRA、参考图只放 1 张。跑通了再逐步加。这样万一报错，问题范围最小。

| 出图很慢 / 显存爆（OOM） | 模型太大或尺寸太大 | 换更小量化模型；调小尺寸 / 步数；关掉多余 LoRA |
| 生成了但画廊是空的 | 输出目录没配对 | 把 ComfyUI 自己的 `output` 目录加进 `output_dirs` |
| LoRA 勾了没效果 | 工作流里没有 LoraLoader 节点 | 看后端日志（会明确提示），换一个带 LoraLoader 的工作流 |

### 13.3 H3 视频类

| 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- |
| `ComfyUI 引擎 xxx 不可达` | ComfyUI 没起 | 顶栏点「H3 视频」或「ComfyUI 绘图」启动它 |
| 报「找不到 MiniMaxH3 节点」 | ComfyUI 版本太旧 | 升级 ComfyUI（第 5.4 章） |
| 报缺 `CreateVideo` / `SaveVideo` | ComfyUI 太旧 | 升级 ComfyUI；本工具会自动回退到 VHS 插件（若已装） |
| 生成出来**没有声音** | 提示词里没写声音段落 | 补上 `overall_soundscape` 和 `non_diegetic_music`（第 12.3 章） |
| 每镜的角色长得不一样 | 没用九宫格 / 没带角色圣经 | 用第 12.4 章的九宫格 + 固定身份描述句 |
| 两镜接起来跳 | 缺首尾帧衔接 / 风格不统一 | 用第 12.5 章步骤 4 的三个技巧 |
| 显存不足 OOM | 分辨率 / 时长 / 步数太高 | 降到 640×480、4 秒、8 步，关 LoRA |
| 生成到一半超时 | 默认轮询上限 | 配置里 `h3.max_poll` 调大 |
| 视频时长不是我填的秒数 | H3 按 `17k+5` 帧网格取整 | 正常现象，会在你的秒数附近取最接近的合法帧数 |

### 13.4 对话 / 优化器类

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 优化器测试连接失败 | Key 错 / 地址错 / 需代理 | 检查接口地址与 Key；如果本机走代理，要把 `127.0.0.1` 加进代理白名单 |
| 报 Cloudflare `error code: 1010` | 某些网关会拦 Python 默认 UA | 本工具已伪装成浏览器 UA；若仍被拦，换一个网关 |
| 本地 LLM 报模型缺失 | `chat_targets` 里模型名不对 | 去「设置 → 模型库」选真实存在的模型；确认 llama-server 已启动 |
| 对话很长就报错 | 上下文超限 | 开上下文压缩；或减少「上下文轮数」；或清空历史 |
| 粘贴超大文本卡死 | —— | 本工具已自动把超长粘贴转成附件处理 |

### 13.5 排错三件套

1. **看日志**：本包 `logs\` 目录。里面是这几个文件（**没有** `backend_*.log` 这种名字）：

   | 文件 | 是什么 |
   | --- | --- |
   | `launcher.log` | 启动器日志：谁启动了后端、用的哪个 Python、浏览器怎么开的、最后怎么退出的 |
   | `ui-YYYYMMDD.log` | **后端主日志**（每天一份）。报错基本都在这里 |
   | `engine-comfy.log` | ComfyUI 自己的输出 —— 「缺模型 / 节点不存在 / 显存爆」都在这 |
   | `engine-llm.log` / `engine-ollama.log` | 本地大模型引擎的输出 |

   页面「设置 → 日志与诊断」里也能直接下拉选文件读，不用自己去文件夹翻。

2. **跑自检**：页面「设置 → 依赖自检」（只查 comfy-cli），再点顶栏「检测运行状态」看引擎。
3. **最小化验证**：把参数调到最小（1 张图、8 步、512×512）再试，看是配置问题还是资源问题。
4. **怀疑 bat 坏了**：双击 bat 后如果**什么窗口都没弹、`logs\launcher.log` 也没有新增行**，说明 bat 本身没跑起来
   （最典型原因是被人手改坏了，见第 15.5 章第 7 条）。用命令行直接跑 `python comfy_studio_launch.py` 绕开 bat 验证，
   能起来就说明是 bat 的问题。

## 15. 代码结构（给二次开发 / AI 接手）

想把包丢给 AI 继续改？按这个地图读最快。

### 15.1 一次「文生图」的请求链路

```
浏览器 (comfy_studio.html)
  → POST /api/...            (comfy_studio.py 的 do_POST 路由分发)
  → comfy_control.run_workflow()
      → convert_ui_to_api(读 workflows/txt2img.json)   # UI 格式 → API 格式，并剔除纯展示节点
      → POST http://127.0.0.1:8188/prompt              # 直连 ComfyUI
      → 轮询 /history 拿结果
  → 后端把图片写进 output/，回传前端显示
```

### 15.2 一次「H3 视频」的请求链路

```
浏览器 (H3 页)
  → POST /api/h3
  → comfy_studio.run_h3(opts)
      → 检查 H3.mode
         ├─ "comfy"（默认）→ h3_run()
         │     → h3_build_workflow(opts)
         │         ├─ 有参考图 → MiniMaxH3ReferenceToVideo (Ref2VA)
         │         └─ 无参考图 → MiniMaxH3ImageToVideo     (T2VA)
         │         → UNETLoader / CLIPLoader / VAELoader×2 / MiniMaxH3SigmaShift
         │         → KSampler → VAEDecode + VAEDecodeAudio
         │         → CreateVideo + SaveVideo（原生；老引擎回退 VHS_VideoCombine）
         │     → POST /prompt，轮询 /history（最长 3600 秒）
         └─ 远程端点 → POST {endpoint}/v1/h3，按 job_status_url 轮询
```

### 15.3 关键模块职责

**`comfy_studio.py`（后端）**
- `do_GET` / `do_POST`：所有 HTTP 路由入口，按 `self.path` 前缀分发。
- `h3_build_workflow(opts)`：**H3 工作流组装核心**。参考图上限 9 张（`refs[:9]`）。
- `h3_combine_kind(base)`：探测目标引擎用哪种视频合成节点（原生 `CreateVideo+SaveVideo` 优先，否则 VHS），结果按 base 缓存。
- `chat_stream`：对话流式转发（支持图片附件透传）。
- `run_h3` / `h3_run`：H3 提交与轮询。
- 配置读写：逐键合并（防止覆盖用户其它设置）。

**`comfy_control.py`（ComfyUI 驱动）**
- `convert_ui_to_api(wf)`：**核心转换**。UI 工作流 → API 格式；转换后剔除无输出的纯展示节点（如 `ImageCompare`），避免新版核心节点必填输入缺失导致 `/prompt` 校验失败。
- `cmd_run` / `run_workflow`：提交与轮询；直连不可用则回退 `comfy run --workflow`。
- `status()`：探测 ComfyUI 是否可达。

**`comfy_engine.py`（引擎管理）**
- `default_engines()`：默认引擎定义（`comfy` / `llm` / `ollama`）。**注意**：配置是「默认值 + 配置覆盖」，配置**删不掉**默认键。
- `start_engine` / `stop_engine`：启停，含「进程 + 端口 + HTTP 探针 + 显存」四层真实检测、互斥、彻底清理（`taskkill /T` 杀整棵进程树）。

**`comfy_studio_launch.py`（启动器）**
- 单实例：8777 已在监听 → 直接开浏览器。
- 浏览器模式：`daily` / `system` / `isolated`。
- **页面注册表**（不是单一「关闭信标」）：前端加载时登记 `GET /api/app/pageopen?pid=<页面id>`，每 5 秒续期 `GET /api/heartbeat?pid=<id>`，卸载时用 `sendBeacon` 注销 `POST /api/app/pageclose?pid=<id>`。后端按 page_id 逐个记账，**一个页面都不剩且持续 `page_empty_hold_sec`（默认 15 秒）** 才停引擎退出。

### 15.5 几个「坑」（前人踩过的，别再踩）

1. **`groups` 必须是数组**，写成对象会让前端崩。
2. **`chat_targets` 会被 `.items()` 遍历**，所以**不能**往里塞 `_注释` 之类的非对象键。
3. **顶层**的 `_xxx` 注释键是安全的（代码用 `CONFIG.get("具体键")` 读取，不会遍历 CONFIG）；但**嵌套结构里**要小心（见第 2 条）。
4. **`.url` 快捷方式指向中文文件名会失败**（`file:///` 的百分号编码会被当 ANSI 解析成乱码）→ 用 `.lnk`。
5. **代理环境**：如果本机挂了 HTTP 代理，访问 `127.0.0.1` 也要绕过代理，否则会出现「假 502」。本工具的脚本启动时会自动清理代理变量。
6. **本地模型用 Python 默认 UA 请求某些网关会被 Cloudflare 拦**（`error code: 1010`）→ 请求要伪装成浏览器 UA。本工具已内置。
7. 🔴 **`.bat` 里 `if ( ... )` 块内的 `echo` 文本不能出现裸圆括号 `(` `)`** —— 这是本项目**真实踩过的致命坑**。
   块里的 `)` 会被 cmd 当成「语句块到此结束」，于是整个 bat 语法报错（中文系统提示 `此时不应有 xxx。`），
   **双击之后后端根本起不来，而且不弹任何窗口**，看起来就像"点了没反应"，极难查。
   要写括号就转义成 `^(` `^)`，或者干脆别用括号。本包 `启动Comfy第三方前端.bat` 已按「块内不用括号」重写，
   **你手改时千万别把括号加回去**。
8. **从别的程序里"帮你去调这个 bat"要小心**：各家 shell 的引号 / 编码规则不一样，中文文件名容易被搞乱。
   （实测：PowerShell 里 `& ".\启动Comfy第三方前端.bat"` 在纯英文路径和 `D:\_zt\Comfy第三方前端` 这种中文路径下**都能正常启动**；
   但从 Node / Python 里拼命令行调 bat 就容易出事。）
   要在命令行启动，**直接跑 `python comfy_studio_launch.py`（绕开 bat）最稳**；`--stop` / `--no-browser` / `--tab` 它都认。
9. **comfy-cli 装错地方等于没装**（第 5.3 章）：它必须在**跑后端的那个 Python** 里，装到 ComfyUI 的 venv 里没用。
10. **关标签页 = 停引擎**（第 8.2 章）：没有页面在看并持续 15 秒，后端会**连正在跑的任务一起停掉**。长任务期间别关页面。
11. 🔴 **CDP 调试端口是「动态」的，别硬编码**（第 15.6 章）：默认 `remote_debug_port = 0` 表示**交给 Chrome 自己挑端口**（实测挑到过 1160，也见过 9411~9415 段）。
    外部工具/AI 想接管页面，**必须去读 `data\browser_cdp.json`**（或 `GET /api/app/cdp`），不能假设 9222 / 9411。
12. **`daily` / `system` 模式下没有 CDP**（Chrome 136+ 起 `--remote-debugging-port` 对默认 profile 一律失效）。
    此时 `browser_cdp.json` 里 `cdp=false`、`alt` 字段会给出替代指引。**要自动化就必须把 `browser_mode` 改成 `isolated`。**

### 15.6 让 AI / 外部工具接管这个页面（想自动化就看这节）

如果你（或者你的 AI）想**用程序去点这个界面**，按下面顺序做，不要靠猜：

| 步骤 | 做什么 | 怎么确认成功 |
| --- | --- | --- |
| 1 | 把 `comfy_studio_config.json` → `app.browser_mode` 改成 `"isolated"` | 只有这个模式才开 CDP |
| 2 | 正常启动（双击 bat 或 `python comfy_studio_launch.py`） | `logs\launcher.log` 出现 `CDP 就绪：http://127.0.0.1:<端口>/json/version` |
| 3 | **读端口**：打开 `data\browser_cdp.json`，取 `port` 字段 | 文件里 `"cdp": true`、`"port": 1160`（示例，你的会不一样） |
| 4 | 或走接口：`GET http://127.0.0.1:8777/api/app/cdp` | 返回同样的 JSON |
| 5 | 列页面：`GET http://127.0.0.1:<port>/json/list`，取 `type == "page"` 那条的 `webSocketDebuggerUrl` | 里面 `url` 应该是 `http://127.0.0.1:8777/` |
| 6 | 连上 WebSocket，用 `Runtime.evaluate` 读 DOM、`Page.captureScreenshot` 截图 | 能读到 `document.title` = `Comfy 第三方前端 · 本地 AI 创作工作台` |

`data\browser_cdp.json` 长这样（**这是实跑抓下来的真样子**）：

```json
{
  "mode": "isolated",
  "cdp": true,
  "port": 1160,
  "http": "http://127.0.0.1:1160",
  "version_url": "http://127.0.0.1:1160/json/version",
  "targets_url": "http://127.0.0.1:1160/json",
  "page_url": "http://127.0.0.1:8777",
  "browser": "Chrome",
  "exe": "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe",
  "user_data_dir": "D:\\ComfyFrontend\\data\\browser-chrome",
  "alt": "",
  "ts_h": "2026-09-25 19:05:52"
}
```

> 想固定端口就改 `app.remote_debug_port`：`-1` = 关掉调试端口，`0` = Chrome 自动分配（默认），`>0` = 你指定（被占用时会自动退到 `cdp_port_candidates` 里的候选端口）。
> 页面上还有 `GET /api/heartbeat?peek=1` 可以看「当前有几个页面在看」（`pages` 字段），做自动化巡检时很有用。
